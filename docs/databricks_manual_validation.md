# Databricks Manual Validation (Production Follow-Up)

This document captures a **manual validation** of the production Delta write
pattern using data generated by the existing pipeline. It is **not** a full
Airflow-to-Databricks integration and does not change current pipeline behavior.

## Validation flow executed

1. Ran the existing Airflow DAG locally for three logical dates:
   - `2024-01-01`
   - `2024-01-02`
   - `2024-01-03`

2. The mock Delta-like sink produced:
   - `169` rows per date
   - `507` total rows

3. Converted the JSONL output into `fx_rates_pipeline_sample.csv`.

4. Uploaded the CSV into Databricks Free Edition as:
   - catalog: `workspace`
   - schema: `default`
   - table: `fx_rates_pipeline_sample`

5. Created a staging Delta table:
   - `fx_rates_staging`

6. Created a target Delta table:
   - `fx_rates_target`

7. Seeded the target table with:
   - one existing key for `USD/EUR` on `2024-01-01` with `rate = -1.0`, to prove that `MERGE` updates matched rows;
   - one target-only row with `quote_currency = 'ZZZ'`, to prove that rows not present in staging remain untouched.

8. Ran a Delta `MERGE INTO` from staging into target using this natural key:
   - `rate_date`
   - `base_currency`
   - `quote_currency`

9. Documented the observed validation results:
   - target row count after first `MERGE`: `508`
   - `EUR` row was updated from staging
   - `ZZZ` target-only row was preserved
   - second `MERGE` run kept row count at `508`, proving no duplicate rows were created
   - Databricks `DESCRIBE HISTORY fx_rates_target` showed:
     - `operation = MERGE`
     - `numSourceRows = 507`
     - `numTargetRowsInserted = 506`
     - `numTargetRowsUpdated = 1`
     - `numTargetRowsMatchedUpdated = 1`
